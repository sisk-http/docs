# Sisk DocFX Documentation Guidelines

- Treat this workspace as the source for the Sisk documentation site built with DocFX, Bun, and the custom `build.js` script.
- Prefer editing the English source documentation under `docs/` and root documentation files. Do not manually edit localized documentation under `docs/ru/`, `docs/pt-br/`, `docs/cn/`, `docs/es/`, `docs/de/`, or `docs/jp/`; those files are generated by the translation flow.
- Do not manually edit generated API/reference output such as `api/*.yml`, `_site/**`, `_md/**`, or `_pack/**`. For API documentation changes, update the upstream source/XML docs in the framework repository instead of patching generated files here.
- Keep DocFX navigation changes in the relevant `toc.yml` files and make links relative and stable for the static documentation site.
- Use the existing Bun scripts in `package.json`: `bun run build:docs` for documentation build validation, `bun run pack` only when the full clean/translate/build flow is needed, and `bun run clean` or `bun run translate` for their specific tasks.
- Avoid running translation or AI-backed flows unless the user asks for them, because they can modify many generated localized files and may depend on external services.
- Preserve the repository's simple JavaScript style in `build.js`: CommonJS modules, direct Node APIs, and small focused changes instead of introducing TypeScript or extra build tooling.
- For documentation text, use clear, task-oriented explanations with accurate Sisk terminology, practical examples, and cross-references when they help the reader choose the next step.
